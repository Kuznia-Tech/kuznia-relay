4.0  THE CORE RULE

Checks find. Fix rounds fix. Re-checks prove it.

4.1 CHECK. Findings with ID, severity, file:line. No fixing.

4.2 LOG. Severity sets the decision. No meeting.

4.3 FIX. Only listed IDs, a failing-first test or proof command each.

4.4 RE-CHECK. Verify each old finding, then only what changed.

SeverityDecisionExample
BlockerFix nowWrong behaviour
Should fixFix nowMissing test
NitBacklogNaming, polish

ROUND LIMIT: third check of the same step still has a blocker, or a finding reopened twice? The loop stops and the owner chooses: split the task, rewrite the spec, or change the approach.

This is the single most important rule. A reviewer that also fixes destroys the evidence trail. Here every finding has an ID that is never reused, every fix has a test that fails on the old code (or a command that proves it), and a fresh agent confirms it. The round limit stops endless ping-pong.
