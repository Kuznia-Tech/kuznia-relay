DECISIONS

Small calls are decided. Big calls stop.

Decide, log, continue

  • A string the design doesn’t cover
  • Engineering option A or B
  • A status code that keeps existing behaviour
  • A new estimate (size never stops work)

Each call is one row in Decisions.md, marked to review: question, options, pick, why, who. Reversed? It becomes a finding.

Stop for the owner

  • Spec and code approval
  • Anything a client, designer or stakeholder must answer
  • Scope or acceptance-criteria changes
  • Round limit, force push, merge conflict, red suite

A written source precedence in RELAY.md settles conflicts, e.g. dated decisions → tickets and acceptance criteria → design. Unsettled? Keep current behaviour and report it.

This is what lets work run overnight without a human. Trivia never blocks; anything that touches scope, requirements or the client always does. The owner reviews the decision log when convenient. In our case study, roughly 800 calls were made without stopping the engineer and logged for review.
